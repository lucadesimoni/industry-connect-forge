# MQTT Broker Configuration for a UNS‑ and AAS‑safe Topic Structure

This document describes how to configure an MQTT broker so that it carries the
topic namespaces generated by this application in a way that is compatible with

- **UNS** (Unified Namespace, ISA‑95 hierarchy Enterprise → Site → Area → Line → Cell),
- **MQTT 3.1.1 / 5.0** (OASIS) topic rules,
- **Sparkplug B 3.0** (Eclipse Foundation),
- **AAS** (Asset Administration Shell, IEC 63278 / IDTA‑01001…01005),
- **IEC 81346** reference designations (RDS).

The rules below are not only recommendations: the topic generators in
`src/lib/mqttTopics.ts`, `src/lib/hierarchyUtils.ts`, `src/lib/sparkplugPayload.ts`
and `src/lib/trackingTopics.ts` enforce them, and `src/lib/__tests__/` tests them.

---

## 1. Topic namespaces produced by the application

Example hierarchy: `Pilatus / Stans / Hall-3 / Line 01 / CNC 5`

| Namespace | Pattern | Example | Purpose |
|---|---|---|---|
| UNS state | `{Enterprise}/{Site}/{Area}/{Line}[/{Cell}]` | `Pilatus/Stans/Hall-3/Line_01/CNC_5` | Current state of each ISA‑95 node (plain MQTT, JSON) |
| Location projection | `enterprise/locations/{Site}/{Area}/{Line}` | `enterprise/locations/Stans/Hall-3/Line_01` | Where things are (Track & Trace view of the UNS) |
| Assets at location (filter) | `enterprise/locations/{…}/assets/+/#` | `enterprise/locations/Stans/Hall-3/Line_01/assets/+/#` | **Subscription filter only**, discovers tracked assets |
| Tracked asset identity | `enterprise/assets/{assetId}/{telemetry\|status\|events}/…` | `enterprise/assets/urn:acme:tracked:container:box-1/status/state` | Stable identity of carriers/containers |
| Asset at location | `enterprise/locations/{path}/assets/{assetId}` | `enterprise/locations/plant-ch/line-3/assets/…` | Current location of a tracked asset |
| Context binding | `enterprise/contexts/{type}/{contextId}/assets/{assetId}` | `enterprise/contexts/order/PO-471193/assets/…` | Order / work order / shipment binding |
| Sparkplug edge node | `spBv1.0/{Enterprise}/{N*}/{Site-Area-Line}` | `spBv1.0/Pilatus/NDATA/Stans-Hall-3-Line_01` | Edge gateway per line |
| Sparkplug device (Cell / AAS) | `spBv1.0/{Enterprise}/{D*}/{Site-Area-Line}/{device}` | `spBv1.0/Pilatus/DDATA/Stans-Hall-3-Line_01/CNC_5` | Machines; AAS submodels are published as metrics |
| Sparkplug host state | `spBv1.0/STATE/{hostId}` | `spBv1.0/STATE/scada-primary` | Primary host application online state (Sparkplug 3.0) |

Mapping rules used by the generators:

- **Sparkplug `group_id`** = Enterprise, **`edge_node_id`** = Site‑Area‑Line joined with `-`,
  **`device_id`** = Cell name, AAS `idShort` or RDS designation without its location
  (e.g. `=M1-DRV1`). Sparkplug only has these three ID levels, so the deeper ISA‑95
  levels are folded into the edge node ID.
- An AAS linked to a **Cell** publishes on the edge node of that Cell's **Line**, so
  it shares the edge node with the Cell's own device topics.
- AAS submodel elements become Sparkplug **metrics** named
  `{SubmodelIdShort}/{Collection}/{Property}`, for example
  `OperationalData/SpindleSpeed`. DBIRTH and DDATA use the same aliases.
- The UNS topic tree stops at the Cell (machine) level. Everything below it is
  modelled by AAS submodels and carried in the payload (Sparkplug metrics or JSON),
  **not** as further topic levels.

## 2. Naming rules (enforced by the generators)

| Rule | Source | Implementation |
|---|---|---|
| Topics are case‑sensitive UTF‑8, 1…65535 bytes, no `U+0000` | MQTT §4.7 | `validateMqttTopicName` |
| `+` and `#` only in subscription filters; `#` only as the last, whole level; `+` only as a whole level | MQTT §4.7.1 | `validateMqttTopicFilter`, `sanitizeTopicLevel` |
| No leading `/`, no empty levels (`//`), no trailing `/` | best practice (HiveMQ, ThingsBoard) | `normalizeTopicPath` |
| No whitespace (replaced by `_`) | best practice | `sanitizeTopicLevel` |
| Never publish to `$…` topics (reserved: `$SYS`, `$share`, `$sparkplug`) | MQTT §4.7.2 | warning in `validateMqttTopicName` |
| Sparkplug IDs must not contain `+`, `/` or `#` | Sparkplug 3.0 | `sanitizeSparkplugId`, `parseSparkplugTopic` |
| Device messages (`D*`) have exactly 5 levels, node messages (`N*`) exactly 4 | Sparkplug 3.0 | `parseSparkplugTopic` |
| AAS identifiers (`id`, `globalAssetId`) are IRIs and contain `/` and `:`: **never use them as topic levels**. Use `idShort` (AASd‑002: `[a-zA-Z][a-zA-Z0-9_-]*`, max. 128) and put the IRI in the payload (`AAS/AssetId` metric) | IDTA‑01001 | `generateAASSparkplugTopic`, `validateIdShort` |
| RDS codes contain only `A–Z0–9`; `.` separates levels; `=`, `-` and `+` are aspect prefixes | IEC 81346‑1 | `sanitizeRDSCode`, `validateRDSDesignation` |

> **Why not the AAS IRI in the topic?** `https://acme.com/assets/robot/0001` would
> create four extra topic levels and break the Sparkplug structure. If an IRI must
> appear in a topic (for example when bridging AAS server events), encode it
> **base64url without padding**, as the AAS API (IDTA‑01002) does for URL paths.

## 3. Broker requirements

| Setting | Recommendation | Reason |
|---|---|---|
| Protocol | MQTT 5.0 (3.1.1 still works) | Message expiry, user properties, better error codes |
| Transport | TLS 1.2+ only (port 8883); disable plain 1883 outside the lab | IEC 62443 / NIS2 |
| Authentication | X.509 client certificates (edge nodes) or username/password via an IdP; **no anonymous access** | |
| Authorization | Topic ACLs per role (see §4); edge nodes may only write their own Sparkplug subtree | Prevents spoofing of UNS state |
| Retained messages | **Enabled**. UNS state topics are published retained; Sparkplug `STATE` **must** be retained; `NBIRTH`/`DBIRTH`/`NDATA`/`DDATA`/`NCMD`/`DCMD`/`NDEATH`/`DDEATH` **must not** be retained | Sparkplug 3.0 |
| QoS | UNS state: 1. Sparkplug `STATE`: 1. Sparkplug `N*`/`D*`: 0 (spec) | Sparkplug 3.0 |
| Last Will | Edge nodes register `NDEATH` (with `bdSeq`) as Will message, QoS 1, retain false | Sparkplug 3.0 |
| Session persistence | Enabled for host applications (`cleanStart=false` + session expiry) | No data loss on reconnect |
| Max. packet size | ≥ 256 KiB (DBIRTH of an AAS with many submodels can be large) | |
| Topic length / levels | No limit lower than 1 KiB / 32 levels | Deep UNS paths |
| `$SYS` | Readable only by admins / monitoring | Information disclosure |
| Shared subscriptions | Allow `$share/{group}/…` for scaled consumers (historians, AAS server bridges) | MQTT 5 |
| Sparkplug‑aware broker (optional) | Enable if supported (HiveMQ Sparkplug extension, EMQX, …): stores births under `$sparkplug/certificates/#` | Late‑joining consumers get the metric definitions |

## 4. Example: Eclipse Mosquitto 2.x

`mosquitto.conf`

```conf
per_listener_settings false
allow_anonymous false

listener 8883
protocol mqtt
cafile   /mosquitto/certs/ca.crt
certfile /mosquitto/certs/server.crt
keyfile  /mosquitto/certs/server.key
tls_version tlsv1.2
require_certificate true
use_identity_as_username true   # certificate CN = MQTT username

acl_file /mosquitto/config/acl

persistence true
persistence_location /mosquitto/data/
retain_available true
max_packet_size 1048576
max_keepalive 120
max_queued_messages 10000

log_type error
log_type warning
log_type notice
```

`acl` (one block per role; `+`/`#` are allowed in ACL patterns)

```conf
# --- Edge node for Pilatus / Stans / Hall-3 / Line 01 ----------------------
user edge-stans-hall3-line01
# Sparkplug: own edge node and its devices only
topic write spBv1.0/Pilatus/+/Stans-Hall-3-Line_01
topic write spBv1.0/Pilatus/+/Stans-Hall-3-Line_01/+
topic read  spBv1.0/Pilatus/NCMD/Stans-Hall-3-Line_01
topic read  spBv1.0/Pilatus/DCMD/Stans-Hall-3-Line_01/+
topic read  spBv1.0/STATE/+
# UNS state of its own line (plain MQTT / JSON)
topic write Pilatus/Stans/Hall-3/Line_01/#

# --- Sparkplug primary host / SCADA -----------------------------------------
user scada-primary
topic write spBv1.0/STATE/scada-primary
topic read  spBv1.0/#
topic write spBv1.0/+/NCMD/+
topic write spBv1.0/+/DCMD/+/+

# --- Track & Trace service --------------------------------------------------
user track-and-trace
topic write enterprise/assets/#
topic write enterprise/locations/#
topic write enterprise/contexts/#

# --- Read-only UNS consumers (dashboards, historian, AAS server bridge) ------
user uns-reader
topic read Pilatus/#
topic read enterprise/#
topic read spBv1.0/#

# --- Monitoring -------------------------------------------------------------
user monitoring
topic read $SYS/#
```

Variant with `pattern` and the client ID (`%c`) as the edge node ID, if each
edge node uses its Sparkplug `edge_node_id` as MQTT client ID:

```conf
pattern write spBv1.0/Pilatus/+/%c
pattern write spBv1.0/Pilatus/+/%c/+
pattern read  spBv1.0/Pilatus/NCMD/%c
pattern read  spBv1.0/Pilatus/DCMD/%c/+
```

## 5. Example: HiveMQ / EMQX

- **HiveMQ**: use the Enterprise Security Extension (ESE) for certificate/IdP
  authentication and topic permissions with the same patterns as in §4. Enable the
  Sparkplug extension if late‑joining consumers need birth certificates.
  In `config.xml`, `<mqtt><retained-messages><enabled>true</enabled></retained-messages>`
  and set `<max-packet-size>` ≥ 256 KiB.
- **EMQX**: authorization via ACL rules (`{allow, {user, "edge-…"}, publish, ["spBv1.0/Pilatus/+/Stans-Hall-3-Line_01/#"]}`),
  deny everything else (`{deny, all}`), `mqtt.max_packet_size = 1MB`,
  `mqtt.retain_available = true`.

## 6. Payload conventions

| Namespace | Payload |
|---|---|
| `spBv1.0/…` | Sparkplug B protobuf (the app shows the JSON representation). Each metric carries `name`, `alias`, `datatype`, `timestamp`, and `is_null` when the AAS property has no value. Metric properties: `unit`, `description`, `semanticId` (ECLASS IRDI / IDTA IRI). |
| UNS state (`{Enterprise}/…`) | JSON with at least `timestamp` (ISO 8601 UTC), `value` and optionally `unit` and `semanticId`, so that consumers can resolve the meaning through the AAS ConceptDescription. |
| `enterprise/assets/…` | JSON event or state document of the tracked asset (see `.lovable/plan.md`). |

AAS → Sparkplug data types (from `mapValueTypeToSparkplug`):

| AAS `valueType` | Sparkplug |
|---|---|
| `xs:double`, `xs:decimal` | Double |
| `xs:float` | Float |
| `xs:long`, `xs:integer` | Int64 |
| `xs:int` | Int32 |
| `xs:short` | Int16 |
| `xs:byte` | Int8 |
| `xs:boolean` | Boolean |
| `xs:dateTime`, `xs:date` | DateTime (ms since epoch, UTC) |
| everything else (`xs:string`, `xs:anyURI`, …) | String |

## 7. Checklist before go‑live

- [ ] Anonymous access disabled, TLS only, certificates rotated.
- [ ] One ACL block per edge node; edge nodes cannot write outside their own subtree.
- [ ] Primary host publishes `spBv1.0/STATE/{hostId}` retained with QoS 1.
- [ ] Edge nodes register `NDEATH` as Will message (QoS 1, retain false).
- [ ] UNS state topics are published retained; Sparkplug data topics are not.
- [ ] `max_packet_size` covers the largest AAS DBIRTH.
- [ ] Topic names were taken from the app (UNS dialog → topic preview) or validated
      with `validateMqttTopicName` / `parseSparkplugTopic`.
- [ ] No AAS IRI is used as a topic level.
